## $(date +%Y-%m-%d) - X-Forwarded-For IP Spoofing Prevention
**Vulnerability:** The `ProxyMiddleware` was vulnerable to IP spoofing because it blindly extracted the first (leftmost) IP address from the `X-Forwarded-For` header using `clientIP = strings.TrimSpace(ips[0])`, without verifying the trust chain of intermediate proxies.
**Learning:** When deploying applications behind proxies or load balancers, the `X-Forwarded-For` header is simply a string appended to by each proxy. An attacker can supply a fake `X-Forwarded-For` header in their initial request, which gets prepended to the chain. Blindly trusting the first element allows attackers to spoof their IP, bypassing rate limits and access controls.
**Prevention:** Always parse `X-Forwarded-For` from right-to-left. The rightmost IP is the proxy closest to the server. Iterate backwards through the chain, verifying each IP against a list of trusted proxies. The first untrusted IP encountered is the true client IP. If all IPs are trusted, the leftmost IP can be used.
## $(date +%Y-%m-%d) - CI Vulnerability Scan Failures
**Vulnerability:** CI failed on `Govul` check due to vulnerabilities in the standard library (`GO-2026-5856` in `crypto/tls` for go1.26.4) and module dependencies (`GO-2026-5970` in `golang.org/x/text@v0.38.0`).
**Learning:** Always keep the language version and dependencies up to date. Vulnerability scans in CI will block PRs if standard library or dependency vulnerabilities are found.
**Prevention:** Monitor dependencies regularly using tools like Dependabot or renovate, or run `govulncheck` locally during development. Bump the Go version and run `go get -u -t ./...` followed by `go mod tidy` to update third-party modules.
