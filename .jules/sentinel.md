## 2026-07-24 - Fix Open Redirect / CRLF Injection in SafeRedirect
**Vulnerability:** The `SafeRedirect` function was vulnerable to open redirects via HTTP response splitting. By appending carriage returns (`\r` or `%0D`) and newlines (`\n` or `%0A`), an attacker could manipulate the URL parser to treat the redirect payload as a path rather than a host, bypassing the `ref.Host` validation check and successfully redirecting to arbitrary domains (or injecting malicious headers in older environments).
**Learning:** Even though `net/http` provides some native protection against CRLF injection in `http.Redirect`, custom URL validation logic using `url.Parse` can be bypassed if malicious whitespace or line breaks are present. The parsing engine strips or alters these characters in unexpected ways, rendering simple host matching ineffective.
**Prevention:** Always explicitly strip carriage returns (`\r`, `%0D`) and newlines (`\n`, `%0A`) from user-supplied redirect parameters *before* attempting to parse or validate the URL.
