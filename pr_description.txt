💡 What: Replaced `fmt.Sprintf` and `sha256.New().Write()` in cache key generation with `strconv` and string concatenation across handlers (Dashboard, OSINT, FortiGuard, Session).

🎯 Why: `fmt.Sprintf` uses reflection and allocates memory for every call, and `sha256.New().Write()` causes the internal hash state to escape to the heap. In hot paths like the Dashboard metrics endpoint or background sync workers, these allocations add up to unnecessary GC pressure and CPU overhead.

📊 Impact: Reduces memory allocations and CPU cycles for cache key generation. Benchmarks on the Dashboard metrics query cache key generation showed a measurable improvement.

🔬 Measurement: Run `go test -bench=BenchmarkDashboardHandler -run=^$ ./internal/web` to verify performance characteristics of the dashboard handler. Check system memory usage over time as background jobs sync feeds.
